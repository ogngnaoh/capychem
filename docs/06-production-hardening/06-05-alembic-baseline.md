# Slice 06-05 — Alembic baseline (enabling gate for milestone 07)

**Status:** shipped (frozen)

## Goal
Replace the drop-recreate dev pattern with Alembic so future schema changes are migrations and real local runs survive a schema bump. The baseline exactly reproduces today's `create_all` schema (no schema change).

## What shipped
- Deps: `alembic>=1.13` + `psycopg[binary]>=3.1` (sync driver — asyncpg is async-only; Alembic's migration context is sync).
- `alembic.ini` (repo root) + `packages/core/capychem/db/migrations/` (`env.py` with `target_metadata = Base.metadata`, sync-URL derivation asyncpg→psycopg, `compare_type=True`; `script.py.mako`).
- `versions/0001_baseline.py` — autogenerated (not hand-written) against an empty DB; `CREATE TABLE` for all 6 models + indexes.
- `packages/core/capychem/db/migrate.py` — `sync_database_url()` + `run_migrations()`: **adopt-or-upgrade** — if `runs` exists but `alembic_version` doesn't (a pre-Alembic create_all DB), `command.stamp(cfg, "head")` first (so upgrade doesn't try to re-create existing tables); then always `command.upgrade(cfg, "head")` (fresh DB → baseline builds all; adopted/current → no-op).
- `apps/api/capychem/api/main.py:31` — `await init_schema(engine)` → `await asyncio.to_thread(run_migrations)` (sync Alembic off the event loop). Startup sweep (lines 35-42) untouched — that's 06-06.
- `db/session.py` + `db/models.py` — retired the "drop/recreate, Alembic deferred" docstrings; `init_schema`/`create_all` kept for ephemeral test DBs.
- `CONTRIBUTING.md` + `README.md` — `alembic upgrade head` (also auto-applied on API startup).
- `packages/core/tests/test_migrations.py` — spins up a throwaway DB, `upgrade head`, asserts `alembic.autogenerate.compare_metadata` is EMPTY (baseline == models); skips if Postgres unreachable; drops the DB.

## Acceptance — met (independently re-verified)
- Fresh-build: `alembic upgrade head` on an empty DB builds all 6 tables + `alembic_version`; `compare_metadata` diff empty.
- Adopt: on the existing create_all dev DB (no `alembic_version`), `run_migrations()` stamps to `0001` then upgrade is a no-op (no re-create error); idempotent on re-run. Dev DB now at `alembic_version = 0001` (verified via psql).
- `test_migrations.py::test_baseline_matches_models` → 1 passed (independent re-run).
- `mypy -p capychem -p capychem.api` → 47 files clean; `ruff check` clean (independent re-run).
- Full `pytest` green (startup lifespan now runs Alembic; API tests use create_all, unaffected).

## Notes
- Tests bootstrap via `init_schema`/create_all (fast, ephemeral); the app boots via Alembic. Both equal at baseline; every future schema change must update models.py AND add a migration to keep them equivalent.
- A stale pre-session `uvicorn --reload` was auto-reloading and re-invoking migrations against the shared dev DB; it was stopped during the build. Restart with `uv run uvicorn capychem.api.main:app --reload` if needed.
